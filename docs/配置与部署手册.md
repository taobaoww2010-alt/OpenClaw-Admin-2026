## 1. 环境要求

### 1.1 最低要求

| 项目 | 要求 |
|------|------|
| Node.js | >= 18.0.0（推荐 20+） |
| npm | >= 9.0.0 |
| 内存 | >= 2GB |
| 磁盘 | >= 500MB（不含备份数据） |
| 操作系统 | macOS / Linux / Windows |
| Python | >= 3.10（仅 Hermes CLI 终端需要） |

### 1.2 网络要求

- **必须部署在 OpenClaw Gateway 所在节点**，或能直接访问 Gateway
- Gateway 地址仅支持 `127.0.0.1` 或 `localhost`（安全限制）
- 开放端口：前端默认 `3001`，后端默认 `3000`

### 1.3 可选依赖

| 功能 | 依赖 | 说明 |
|------|------|------|
| 远程终端 | node-pty | 自动安装，Linux 需要 `build-essential` |
| 远程桌面 | xvfb, x11vnc | 仅 Linux 远程桌面需要 |
| Hermes CLI | Python 3.10+ | 仅使用 Hermes CLI 终端时需要 |

## 2. 快速安装

### 2.1 获取代码

```bash
# 方式一：克隆仓库
git clone https://github.com/itq5/OpenClaw-Admin.git
cd OpenClaw-Admin

# 方式二：下载 ZIP 并解压
```

### 2.2 安装依赖

```bash
npm install
```

> **注意**：`node-pty` 需要编译原生模块，Linux 上可能需要先安装编译工具：
> ```bash
> # Ubuntu/Debian
> sudo apt-get install -y build-essential python3
> 
> # CentOS/RHEL
> sudo yum groupinstall -y "Development Tools"
> ```

### 2.3 初始化配置

```bash
# 复制环境变量模板
cp .env.example .env

# 编辑配置
nano .env   # 或 vim .env
```

### 2.4 验证安装

```bash
# 构建验证
npm run build

# 如果输出无错误，说明安装成功
```

## 3. 环境变量配置

### 3.1 完整配置说明

编辑 `.env` 文件，以下是所有可用变量：

```ini
# ============================================
# 应用基础配置
# ============================================

# 应用标题（显示在浏览器标签和页面顶部）
VITE_APP_TITLE=Daoyi-Claw

# ============================================
# OpenClaw Gateway 配置（必须）
# ============================================

# Gateway WebSocket 地址
# 注意：必须使用 localhost 或 127.0.0.1
OPENCLAW_WS_URL=ws://localhost:18789

# 认证方式（二选一）：
# 方式一：使用 Token（推荐）
OPENCLAW_AUTH_TOKEN=your-token-here

# 方式二：使用密码
OPENCLAW_AUTH_PASSWORD=

# ============================================
# 端口配置
# ============================================

# 后端服务端口（生产环境使用）
PORT=3000

# 前端开发服务器端口（开发环境使用）
DEV_PORT=3001

# ============================================
# 登录认证配置
# ============================================

# 登录用户名（留空则禁用登录验证）
AUTH_USERNAME=admin

# 登录密码（留空则禁用登录验证）
AUTH_PASSWORD=admin

# ============================================
# 日志配置
# ============================================

# 日志级别：DEBUG / INFO / WARN / ERROR
LOG_LEVEL=INFO

# ============================================
# Hermes Agent 集成（可选）
# ============================================

# Hermes Web UI 地址
HERMES_WEB_URL=http://localhost:9119

# Hermes API Server 地址
HERMES_API_URL=http://localhost:8642

# Hermes API Key（如果 HERMES_API_KEY 已设置）
HERMES_API_KEY=hermes-local-dev-key

# Hermes CLI 路径（可选，默认自动检测）
HERMES_CLI_PATH=

# Hermes HOME 目录（可选）
HERMES_HOME=

# 是否自动启动 Hermes Dashboard
HERMES_AUTO_START_DASHBOARD=true

# ============================================
# 语音合成 (TTS) 配置
# ============================================

# 是否启用 TTS
VITE_TTS_ENABLED=true

# 是否自动播放语音
VITE_TTS_AUTO_PLAY=false

# 语音语言代码
VITE_TTS_VOICE=zh-CN

# 语速（1.0 为正常）
VITE_TTS_RATE=1.0

# 音量（0.0 - 1.0）
VITE_TTS_VOLUME=1.0

# 音调（1.0 为正常）
VITE_TTS_PITCH=1.0

# ============================================
# 告警推送（可选）
# ============================================

# Telegram Bot Token
# TELEGRAM_BOT_TOKEN=
# TELEGRAM_CHAT_ID=
```

### 3.2 最小配置

如果只是本地快速测试，只需配置以下内容：

```ini
OPENCLAW_WS_URL=ws://localhost:18789
OPENCLAW_AUTH_TOKEN=你的Token
AUTH_USERNAME=admin
AUTH_PASSWORD=admin
```

### 3.3 认证安全说明

| AUTH_USERNAME | AUTH_PASSWORD | 效果 |
|:---:|:---:|------|
| 已设置 | 已设置 | 启用登录验证 |
| 留空 | 留空 | **禁用登录验证**（任何人可直接访问） |

> **强烈建议**：生产环境必须设置用户名和密码。

## 4. OpenClaw Gateway 配置

### 4.1 确认 Gateway 运行

```bash
# 检查 Gateway 是否在运行
ps aux | grep openclaw

# 或使用 openclaw 命令
openclaw status
```

### 4.2 获取 Gateway Token

```bash
# 查看 Token
cat ~/.openclaw/token
# 或
openclaw token
```

### 4.3 使用密码认证（替代 Token）

如果不想用 Token，可以使用 Gateway 密码：

```ini
# 在 .env 中
OPENCLAW_AUTH_TOKEN=        # 留空
OPENCLAW_AUTH_PASSWORD=your-password
```

### 4.4 连接验证

启动 Daoyi-Claw 后，页面右上角的 **OpenClaw** 指示灯变为绿色即表示连接成功。

## 5. Hermes Agent 集成（可选）

### 5.1 前置条件

Hermes Agent 需要单独安装。需要以下服务运行：

| 服务 | 默认端口 | 说明 |
|------|---------|------|
| Hermes Web UI | 9119 | 管理 REST API |
| Hermes API Server | 8642 | OpenAI 兼容 API |
| Hermes CLI | - | Python CLI 工具 |

### 5.2 安装 Hermes Agent

```bash
# 一键安装
curl -fsSL https://raw.githubusercontent.com/NousResearch/hermes-agent/main/scripts/install.sh | bash

# 交互式配置
hermes setup
```

### 5.3 配置 Hermes

#### 设置 AI 模型

```bash
# 交互式选择
hermes setup model

# 或编辑配置文件
vim ~/.hermes/config.yaml
# model: anthropic/claude-sonnet-4
```

#### 设置环境变量

```bash
vim ~/.hermes/.env

# 添加以下内容
API_SERVER_ENABLED=true
GATEWAY_ALLOW_ALL_USERS=true
API_SERVER_KEY=1212
```

#### 启动服务

```bash
# 安装 Gateway
hermes gateway install

# 前台运行（调试）
hermes gateway run -v

# 后台运行（生产）
hermes gateway start

# 启动 Web UI
hermes dashboard

# 验证连接
curl http://localhost:8642/v1/health
curl http://localhost:9119/api/status
```

### 5.4 在 Daoyi-Claw 中连接 Hermes

1. 确保 `.env` 中已配置：
   ```ini
   HERMES_WEB_URL=http://localhost:9119
   HERMES_API_URL=http://localhost:8642
   HERMES_API_KEY=1212
   ```
2. 重启 Daoyi-Claw
3. 页面右上角 **Hermes** 指示灯变为绿色即表示连接成功

## 6. 运行模式

### 6.1 开发模式

```bash
# 仅启动前端（Vite 开发服务器）
npm run dev

# 仅启动后端服务
npm run dev:server

# 同时启动前后端（推荐）
npm run dev:all
```

访问 `http://localhost:3001` 进入管理界面。

### 6.2 生产模式

```bash
# 1. 构建生产包
npm run build

# 2. 启动生产服务（包含后端 + 静态文件）
npm run start
```

生产服务默认监听 `3000` 端口。

### 6.3 运行模式对比

| 特性 | 开发模式 | 生产模式 |
|------|---------|---------|
| 命令 | `npm run dev:all` | `npm run start` |
| 端口 | 前端 3001 / 后端 3000 | 统一 3000 |
| 热更新 | 支持 | 不支持 |
| 类型检查 | 自动 | 构建时检查 |
| 适用场景 | 开发调试 | 生产部署 |

## 7. 生产部署

### 7.1 标准部署流程

```bash
# 1. 拉取最新代码
git pull origin main

# 2. 安装/更新依赖
npm install

# 3. 配置环境变量
cp .env.example .env
nano .env

# 4. 构建
npm run build

# 5. 启动
npm run start
```

### 7.2 使用 PM2 进程管理（推荐）

```bash
# 安装 PM2
npm install -g pm2

# 启动应用
pm2 start "npm run start" --name daoyi-claw

# 查看状态
pm2 status

# 查看日志
pm2 logs daoyi-claw

# 重启
pm2 restart daoyi-claw

# 设置开机自启
pm2 startup
pm2 save
```

### 7.3 使用 Nginx 反向代理

```nginx
server {
    listen 80;
    server_name your-domain.com;

    # 启用 gzip 压缩
    gzip on;
    gzip_types text/plain text/css application/json application/javascript text/xml;
    gzip_min_length 1024;

    location / {
        proxy_pass http://127.0.0.1:3000;
        proxy_http_version 1.1;
        
        # WebSocket/SSE 支持
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        
        # SSE 长连接支持
        proxy_buffering off;
        proxy_cache off;
        proxy_read_timeout 86400s;
    }
}
```

### 7.4 HTTPS 配置

```bash
# 使用 Let's Encrypt 免费证书
sudo apt install certbot python3-certbot-nginx
sudo certbot --nginx -d your-domain.com
```

### 7.5 端口修改

如果 3000 端口被占用，修改 `.env` 中的 `PORT`：

```ini
PORT=8080
```

## 8. 安全加固

### 8.1 修改默认密码

**必须**在生产部署前修改默认密码：

```ini
# .env 文件
AUTH_USERNAME=你的用户名
AUTH_PASSWORD=你的强密码
```

### 8.2 网络安全

- **仅绑定 localhost**：Gateway 地址使用 `ws://127.0.0.1:18789`
- **使用 HTTPS**：生产环境必须启用 HTTPS
- **防火墙**：仅开放必要端口

```bash
# Ubuntu UFW 示例
sudo ufw allow 80/tcp    # HTTP
sudo ufw allow 443/tcp   # HTTPS
sudo ufw enable
```

### 8.3 文件安全

- 文件浏览器有路径遍历保护（`safePath` 函数）
- 上传文件大小限制为 100MB
- 凭证字段掩码显示，不回显明文

### 8.4 会话安全

- 登录 Token 24 小时过期
- 支持主动登出
- SSE 连接需要认证

### 9.1 备份内容

系统备份包含：
- SQLite 数据库（`data/` 目录）
- OpenClaw 配置文件

## 10. 故障排查

### 10.1 启动失败

```bash
# 检查 Node.js 版本
node -v   # 必须 >= 18

# 检查依赖安装
npm ls

# 检查端口占用
lsof -i :3000
lsof -i :3001
```

### 10.2 Gateway 连接失败

| 症状 | 原因 | 解决方案 |
|------|------|---------|
| 红灯常亮 | Gateway 未启动 | `openclaw start` |
| 红灯闪烁 | Token 无效 | 检查 `OPENCLAW_AUTH_TOKEN` |
| 连接超时 | 地址错误 | 确认 `OPENCLAW_WS_URL` 为 `ws://localhost:18789` |

### 10.3 构建错误

```bash
# 类型错误
npm run build

# 如果报错，检查 TypeScript 版本
npx tsc --version

# 清理缓存重试
rm -rf node_modules/.vite
npm run build
```

### 10.4 远程终端无法连接

```bash
# 检查 node-pty 是否正常编译
node -e "require('node-pty')"

# 如果报错，重新编译
npm rebuild node-pty

# Linux 需要安装编译工具
sudo apt-get install -y build-essential
```

### 10.5 日志查看

```bash
# 开发模式日志
npm run dev:server

# PM2 日志
pm2 logs daoyi-claw --lines 100

# 调整日志级别
# 在 .env 中设置
LOG_LEVEL=DEBUG
```

### 10.6 数据库问题

```bash
# 检查 SQLite 数据库文件
ls -la data/

# 数据库文件损坏时的恢复
# 1. 停止服务
# 2. 从备份恢复 data/ 目录
# 3. 重启服务
```
